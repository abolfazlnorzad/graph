Key Design Decisions

  • Transactional Audit Logs: CreateTask and UpdateTask use DB transactions to ensure task + audit log are written atomically
  • Parallel Fetch: GetTask uses goroutines to fetch task (from cache/DB) and audit logs (from DB) concurrently
  • Cache-Aside: Redis caches task data with 5min TTL; list cache invalidated on writes
  • Optimistic Locking: Version field prevents concurrent update conflicts
  • Soft Delete: Tasks are marked with deleted_at, not physically removed
  • Observability: OTLP metrics → Prometheus, OTLP traces → Tempo, Structured logs → Loki
